## 🔴 Открыто (UX / функционал)

### Удобство

- **Селекторы мин-макс** в slot-ranges неудобные. Сейчас `[-] 0 [+] - [-] 1 [+]` на каждый слот. Варианты:
  - Один range-слайдер с двумя ручками (min/max)
  - Тап по числу → bottom-sheet с цифрами 0–9
  - Только max (min всегда 0), а min задаётся отдельной галочкой "обязательно"
- **Подборка**: тап по всему ряду должен открывать пикер, не только по тексту «изменить». _(пофикшено в этом коммите)_
- **Аудит других тап-таргетов** на ту же тему — везде, где маленькая ссылка управляет крупным блоком.
- В пикере подборки добавить **подсчёт по слотам**: «У тебя 3 верха и 0 низов в подборке» — предупреждение если генератор не сможет собрать.
- Список **сохранённых сессий** — навигация между капсулами; сейчас новая сессия создаётся автоматически.
- Возможность **дублировать сессию** (одна и та же подборка, разные диапазоны).

## 🟡 LLM roadmap

Архитектурная развилка — где живёт модель:

- **(W)** Cloudflare Worker как прокси с API-ключом Anthropic. Free tier хватит. ~50 LOC воркера, PWA дёргает `/api/*`.
- **(L)** Локальные WASM-модели (`@imgly/background-removal`, MODNet). Без сети и стоимости, но первый запуск качает ~50 MB.
- **(S)** Сторонние сервисы с CORS (Replicate, remove.bg). Простой fetch с ключом в PWA, но ключ светится в браузере.

### A. Удаление фонов с фоток вещей

- Проблема: уже добавленный trim только режет прозрачные поля. Многие фотки приходят с непрозрачным фоном.
- Тех. пути: WASM (RMBG-1.4 или MODNet, ~50 MB), Replicate API, remove.bg.
- Рекомендация: **WASM локально**. Композится с локальностью PWA, нулевая стоимость, ~5 минут «Перепроверить» для 247 вещей.
- UX: вторая кнопка в upload-sheet — «Убрать фоны (медленно)». Может использовать существующий progress-bar.

### B. Текстовые описания вещей

- Что хранить на `Item`: `description: string`, `tags: string[]`, может ещё `color`, `formality`, `season`.
- Тех: Claude vision через прокси (W). Запрос → JSON.
- Стоимость: Claude Haiku 4.5 vision ~$0.0003/image. 247 вещей ≈ $0.07 единоразово.
- Зачем: поиск по гардеробу, ввод для (C), доступность.

### C. Умная генерация образов

- Два подхода:
  1. **LLM-as-generator**: модель сразу выдаёт списки item id. Дорого, медленно (5–15 сек), не наберёшь 30 за раз.
  2. **LLM-as-ranker**: локальный генератор предлагает 50, модель ранжирует/фильтрует. Дешевле, остаётся офлайн-fallback.
- Рекомендация: **(2)** + поле «что хочется» в сессии. Подключается к (B).
- Совместимо с подборкой: подборка сужает, LLM ранжирует. Ортогональны.

### D. Умный лейаут

- Не нужен LLM в рантайме — нужны метаданные из (B). Расположение акс-ов по якорям (серьги наверху, сумка у бедра).
- Пока низкий приоритет — текущая 3-полосная раскладка устраивает.

### Приоритет последовательности

1. **A** локально-WASM — быстрый win, нет инфраструктуры.
2. **Решить про прокси** (W).
3. **B** — фундамент для C и D.
4. **C v1** как ранжировщик.
5. **D** позже.
