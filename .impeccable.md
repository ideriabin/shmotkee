# Project Design Context

## Design Context

### Users

**Single user** — the developer's wife. Russian-speaking. Uses the app mostly on iPhone and iPad (Chrome on iOS, which means WebKit underneath), occasionally on desktop Chrome. Context: at home, choosing what to wear, often in the evening. She approaches her wardrobe strategically — building outfits is a confident, expressive act, not a chore.

She has a strong, established personal aesthetic: all-black wardrobes, leather/vinyl/mesh/fur materials, a burgundy hair color that is the only consistent warmth in her photography. She uses bold Cyrillic italic overlays on her own Instagram content. She is not the audience for "minimal, friendly, helpful" UI — she is the audience for confident, sharp, opinionated UI that matches her energy.

The job to be done:

1. Build a digital catalog of her real clothes by uploading photos into pre-assigned slots.
2. Generate outfit combinations by locking 0+ specific items and letting a solver fill the rest.
3. Decide on each generated outfit via either a grid (fast skimming) or a Tinder-style swipe view (focused judgement).
4. Save the keepers into a working session and export them as flat-lay PNGs with item captions for Canva.

### Brand Personality

**Three words: defiant, intimate, theatrical.**

- *Defiant* — the buttons say `хуйня` and `заебись`. The app doesn't apologize. It is not a polite SaaS dashboard.
- *Intimate* — single-user, local-only, no analytics, no notifications, no social. It's her closet. Nobody else's.
- *Theatrical* — fashion is performance. The app frames her clothes like an editorial spread, not a checkout flow.

The interface should evoke confidence and a small kick of pleasure on every interaction. Not delight in the cute-mascot sense — delight in the "this thing knows me" sense.

### Aesthetic Direction

**Theme: dark mode only.** Derived from context (evening use, intimate, photo-forward, her own visual world is dark). No light-mode toggle in v1.

**Reference points:**

- Her own Instagram grid: dark interiors, all-black outfits, burgundy hair as the only warm color, editorial photography, assertive Cyrillic italic overlays.
- Editorial fashion print: layout breathes, photos dominate, type pulls weight without screaming.
- Telegraph/RIA "noir editorial" web styling — but stripped of any "designy" tropes.

**Anti-references** (what this must explicitly NOT look like):

- Material Design pastel cards with rounded everything.
- "AI starter template" — neon cyan on near-black, gradients, glassmorphism, sparkle particles.
- E-commerce admin dashboards (no card grids with icon + label + value).
- Soft / cute / friendly / pastel.

**Visual system commitments:**

- **Background**: deeply tinted near-black, never `#000`. `oklch(0.13 0.006 18)` — a hair of red tint.
- **Surfaces**: stepped from background by lightness only, same hue tint.
- **Text**: warm off-white `oklch(0.96 0.005 30)`, muted at `oklch(0.58 0.005 18)`.
- **Accent**: single saturated burgundy red `oklch(0.55 0.18 18)`, reserved for primary action (the `заебись` button, generate CTA, selected state). Used sparingly — it is the only color in the system, so when it appears it carries weight.
- **No gradients on text. No glassmorphism. No drop-shadow-on-rounded-cards.**
- **Borders**: 1px max, low-chroma, used sparingly. Prefer surface stepping for separation.
- **Radii**: 0–2px globally. No pills, no squircles. Sharp.
- **Photography is the hero**: clothing images are the focal point of every screen; UI chrome recedes.

**Typography:**

The visual direction calls for a Cyrillic display italic for hero moments. The first reflex (Cormorant Garamond) is on the impeccable banned list, so revised picks:

- **Display: Yeseva One** (Olga Karpushina, Google Fonts). Single dramatic weight. Strong inscriptional Cyrillic, theatrical and assertive. Used for the wordmark, the "Сгенерировать" CTA, the `заебись` label, and big section titles. One weight means it's used sparingly — when it appears, it lands.
- **UI / body: Onest** (Russian-influenced contemporary geometric sans, full weight range with italic, native Cyrillic). Covers all body text, labels, secondary buttons, captions. Italic from Onest covers most italic moments — keeps the system to two families.

**Scale (rem, no fluid clamp — this is an app UI, not a marketing page):**

| Token        | Size       | Use                                                |
| ------------ | ---------- | -------------------------------------------------- |
| `--text-xs`  | 0.75rem    | Slot chip labels, fine captions                    |
| `--text-sm`  | 0.875rem   | UI labels, meta                                    |
| `--text-md`  | 1rem       | Body                                               |
| `--text-lg`  | 1.25rem    | Item name, list row primary                        |
| `--text-xl`  | 1.625rem   | Tab title, session name in detail                  |
| `--text-2xl` | 2.25rem    | Hero CTA, тиндер view labels                       |
| `--text-3xl` | 3.5rem     | Wordmark, splash hero                              |

**Spacing scale (4pt-based):** 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96.

**Motion:** restrained. Exponential ease-out, 180–280ms. The Tinder swipe drag uses physical translation with momentum into the dismiss/save transition. No bounce, no elastic, no stagger choreography on entry. The app is not trying to entertain.

### Design Principles

1. **The clothes are the content.** Every screen treats the user's clothing photos as the primary visual element. App chrome — buttons, labels, dividers, headers — recedes so the photos can lead.
2. **Sharp over soft.** Right angles or 1–2px radii. Never pillowy. Borders are 1px, low-chroma, used sparingly. Separation comes from surface lightness steps, not box drawing.
3. **One color of consequence.** Burgundy red is the single accent. It marks the action she wants to take. Everything else is neutral. The accent earns its rarity.
4. **Display type is theatrical, UI type disappears.** Yeseva One shows up for moments that matter (wordmark, primary CTA, the хуйня/заебись pair). Onest carries the day-to-day without drawing attention to itself.
5. **Mobile-first, touch-first.** Tap targets are generous, gestures are primary, hover is never required. The desktop layout is an expansion of the mobile one, not a different design.
6. **No defaults.** Every choice — type, color, radius, spacing — should be explicitly considered and traceable to this document. If a default Tailwind value or Material color sneaks in, it's a bug.

### Accessibility

- WCAG AA contrast minimum throughout (text on background, accent on its bg).
- All gestures have button equivalents (swipe-to-save is paired with a button, never gesture-only).
- Touch targets ≥ 44×44 CSS pixels.
- Focus visible: a 2px burgundy outline offset 2px, never the default browser outline-but-also-not-removed.
- `prefers-reduced-motion: reduce` collapses transitions to ≤80ms and disables swipe drag animation.

### Out of Scope (for this design context)

- Branding for marketing — there's no marketing site, the app *is* the brand expression.
- Multi-user theming, internationalization beyond Russian, light mode.
- Print stylesheets.
